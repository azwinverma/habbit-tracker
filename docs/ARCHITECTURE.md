# Architecture (as of Phase 1)

## Layers

```
lib/
├── main.dart                 Firebase (optional) → ads → notifications → ProviderScope(HabitApp)
├── firebase_options.dart     generated by flutterfire (project habbittracker-c2daa)
├── app/
│   ├── app.dart              MaterialApp.router, light/dark/system theme
│   ├── router.dart           GoRouter: /splash, shell(/today /plan /insights /you), /discover
│   ├── app_shell.dart        bottom nav (Today | Plan | Add | Insights | You), Add sheet,
│   │                         triggers content sync on start + resume
│   ├── providers.dart        Riverpod providers (DB, repositories, streams, theme)
│   └── theme.dart            brand tokens (blueprint palette)
├── core/
│   ├── db/                   Drift schema (tables.dart) + AppDatabase (+ generated .g.dart)
│   └── reminders/            planner → registry → native alarms (see NOTIFICATION_ARCHITECTURE)
├── features/
│   ├── habits/
│   │   ├── data/             HabitRepository (SQLite), LegacyHabitMigrator (habits_v1 → DB)
│   │   └── presentation/     HabitFlows (create/open/toggle/delete, shared by all screens)
│   ├── content/
│   │   ├── domain/           ContentItem, ContentKind, LicensePolicy
│   │   ├── data/             providers (Gutendex, Wikimedia, wger), ContentRepository,
│   │   │                     ContentSyncService
│   │   └── presentation/     DiscoverScreen
│   ├── plan/                 PlanScreen (upcoming reminders, reminder health, test reminder)
│   ├── insights/             InsightsScreen (7-day history)
│   └── profile/              ProfileScreen (theme, permissions, content sources, privacy)
├── screens/                  legacy category screens (medicine, water, meditation, reading,
│                             exercise, add/edit, splash, home=Today), migrated in Phase 2/3
├── services/                 StorageService facade, notifications, native alarm backend, ads
├── models/habit.dart         legacy view model used by the category screens
└── widgets/
```

## Data flow
- **Habits:** screens → `StorageService` (old API, kept) → `HabitRepository` → SQLite. `HabitRepository.watchAll()` streams changes to Today, Plan and Riverpod listeners, so edits made anywhere show up everywhere.
- **History:** daily counters (water, meditation, exercise minutes, steps) and completions become rows in `habit_logs` (one per habit, day and metric, idempotent). Insights reads aggregates from there.
- **Reminders:** after a save, `ReminderService.syncHabit()` re-plans alarms from data (unchanged from Phase 0).
- **Content:** `ContentSyncService` → providers → `ContentRepository` (SQLite cache) → Discover, meditation and reading pickers. Everything reads from the local cache, so it works offline.

## Decisions
| Decision | Why |
|---|---|
| Riverpod 2.6, Drift 2.28, GoRouter 17 | Newest versions compatible with the installed Flutter 3.29.3 / Dart 3.7.2 (Drift ≥2.29 and Riverpod 3 need a newer SDK). |
| Keep `Habit` as a view model for now | Lets every existing screen keep working unchanged on top of the normalised DB. Screens move to typed per-category models as they're rebuilt (Phase 2/3). |
| Mirror saves to `habits_v1` | Rollback safety: downgrading to v1.0.0 loses nothing. Also a fallback if the DB can't open. Remove after two stable releases. |
| Content from public APIs directly (no backend yet) | Works today with no server cost. Phase 4/5 adds a Firebase-backed curated catalogue and admin approval on top (same `ContentProvider` interface). |
| minSdk 24 (Android 7.0) | Required by firebase_core 5 / Firebase BoM 34. Drops Android 5–6. |
| Firebase initialised but unused | Project wired (`flutterfire configure`). Auth, Firestore, Analytics and Crashlytics come in Phase 4 with consent and security rules. App works without Firebase. |
